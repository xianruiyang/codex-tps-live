# Codex TPS Live

[简体中文](README.md) | [English](README.en.md)

Windows 本地 Codex 用量与速度监控工具，以只读方式分析本机日志，按对话、轮次和模型响应展示 token、缓存、TPS，并提供速度趋势、额度曲线与容量估算。

基于 [adenta/codex-tps](https://github.com/adenta/codex-tps) v0.2.0（`be54961`），保留上游 MIT 版权声明和离线命令。离线 CLI 的说明见 [docs/offline-cli.md](docs/offline-cli.md)。

## 便携版运行

[下载 Windows x64 便携版](https://github.com/xianruiyang/codex-tps-live/releases/latest/download/codex-tps-live-windows-amd64.zip)，或前往 [Releases](https://github.com/xianruiyang/codex-tps-live/releases) 选择版本。完整解压到任意目录后，双击其中的 `启动监控.cmd`。适用于 Windows 10/11 x64，支持中文和空格路径，无需安装或管理员权限。它启动本机程序并打开默认浏览器；保持控制台运行，按 Ctrl+C 退出。

便携包包含六个文件：`codex-tps-live.exe`、`启动监控.cmd`、中文 `使用说明.md`、英文 `Usage.en.md`、英文 MIT 原文 `LICENSE` 和中文译文 `LICENSE.zh-CN.md`。页面资源内嵌在 exe 中，不需要项目源码、`web` 文件夹、Go、Node、Python、API Key 或联网；不会打包本机 Codex 日志、认证文件或截图。启动器通过自身位置寻找 exe，不依赖盘符、用户名、解压位置或当前工作目录。启动器也支持透传下面的命令行参数。

也可[单独下载 EXE](https://github.com/xianruiyang/codex-tps-live/releases/latest/download/codex-tps-live.exe)，在 PowerShell 中运行；ZIP 另附启动器、双语说明和许可证。Release 的 `SHA256SUMS` 同时提供 ZIP 与 EXE 校验值：

```powershell
.\codex-tps-live.exe --open
```

默认页面为 `http://127.0.0.1:8765`。日志目录依次取 `--codex-home`、当前电脑的 `CODEX_HOME`、当前 Windows 用户目录下的 `.codex`（通常为 `%USERPROFILE%\.codex`）；无需照搬开发电脑的目录。自定义目录应指向含 `sessions` 的 Codex 数据目录。目标电脑还没有日志时，页面提示目录不可用或暂无对话，产生日志后自动发现。页面没有 CDN、外部字体或第三方脚本。

升级时先关闭旧监控程序，再覆盖解压目录中的发布文件并重新启动，原有 Codex 对话不受影响。源码构建会同时更新最新 ZIP 和未压缩的 `dist` 目录；本机直接双击 `dist\启动监控.cmd` 即可运行，也可以将整个 `dist` 目录复制到其他电脑使用。

程序只读日志，不启动 Codex/app-server，不读取认证文件，不代理或修改 Codex 的请求。浏览器只访问本机监听地址。关闭程序即可停止监控；关闭或暂停页面不停止后台采集。它仍会使用本机 CPU、内存和磁盘，不能承诺零资源开销。

## 参数

```powershell
# 指定其他 Codex 日志目录
.\codex-tps-live.exe --codex-home 'D:\my-codex' --open

# 采集全部历史日志，并默认显示归档对话
.\codex-tps-live.exe --days 0 --include-archived --open

# 使用可用的随机本机端口
.\codex-tps-live.exe --port 0 --open

# 调整日志轮询频率
.\codex-tps-live.exe --interval 2s --open

# 自定义额度记录目录和本地资料名（不代表账号识别）
.\codex-tps-live.exe --data-dir 'D:\monitor-data' --quota-profile work --open
```

默认启动发现最近 7 天有更新的 `sessions` 和 `archived_sessions` 文件，按文件更新时间从新到旧处理。已经发现的会话继续保留在当前进程中；新文件每 5 秒发现一次。默认每 0.5 秒增量读取文件和刷新页面。首次从文件尾部定位最近 10 轮的完整边界，并读取前一个累计用量检查点作为基线，再按时间顺序解析选中的轮次。扩大 N 时按需补读更早轮次，期间保留已加载数据并提示进度；缩小 N 后停止不再需要的补读。程序不复制原始日志；重启时从所选日志重新建立对话统计，额度页面另持久保存必要的计量记录。缺少可靠轮次边界或此前累计检查点的旧日志会回退到从头分批解析。

## 面板

- 左侧标签显示当前日志记录的模型和推理档位。子代理优先显示任务路径中的名称，下方显示昵称、角色和任务标题；详情展示完整任务路径。支持名称、昵称、角色、标题、模型、工作目录和 ID 搜索。
- 模型旁显示服务层标签：`ultra fast`、`fast`、`default`、`unknow`，覆盖左侧对话、轮次及每次模型响应。子代理补全的状态标记“继承”；历史响应优先使用自身记录，继承值匹配该轮开始时主对话的记录。
- “全部 / 主对话 / 子代理”独立筛选，可与“进行中”状态筛选组合；父子用量不合并。“显示归档对话”默认关闭，设置保存在当前浏览器；归档对话标记“已归档”。该开关只筛选对话列表，后台采集、消耗记录、速度趋势和额度估算始终包含归档日志。`--include-archived` 兼容为无浏览器偏好时默认显示归档对话，不再控制采集。
- 顶部设置最近 N 轮，默认 **10**。进行中的轮次也计入；左侧用量、卡片、轮次列表和 CSV 导出统一使用该范围。设置保存在当前浏览器的本机站点存储中。
- 左侧对话按最近一次新增、通过去重的模型响应上报时间倒序排列。只有新增响应才更新排序时间，普通日志、状态与模型设置变化只更新显示；暂无响应的新对话按创建时间定位，时间相同时按 ID 固定排序。排序时间独立于最近 N 轮统计范围；补读更早历史不替换最新响应时间。刷新时复用已有标签，内容未变则不重绘，顺序未变则不移动。
- 轮次及轮次内模型响应为最新在前，使用“第 N 轮 / 第 N 次”的正向编号，按编号从大到小显示。尚未读取全部历史时，轮次编号从已加载的最早一轮起算，补读更早历史后重新建立；悬停轮次标签可查看编号范围。已加载轮数不标成全对话总轮数。
- 用户轮次显示输入、缓存命中、缓存写入、输出、预计积分、可见/实际 TPS 和模型响应耗时；展开查看每次模型响应及其首 Token 等待、预计积分。轮次与展开的响应列表分别在框内滚动，标题栏固定。数据不变时保留现有表格；滚动期间将表格更新合并到停下后显示，上方摘要继续更新，避免刷新打断滚轮。
- 左侧每个对话和选中对话的汇总卡显示最近 N 轮的预计积分，轮次积分为其响应之和，对话积分为窗口内轮次之和，均不叠加子代理。按每次响应的实际模型、缓存、输出和最终确认的速度档位计价；不会用当前模型或档位替代历史记录。缺少模型或速度时标为未计价，部分可计价时同时标明覆盖数量，不能把未知消耗当成零。对话明细与额度页共享积分口径及上下文情景选择，切页后保留；这些值是等效积分估计，不是官方扣款记录。
- 对话、轮次、响应及额度页的积分统一显示两位小数；内部计价、汇总和 API 数据保留原精度。
- TTFT 优先使用可归属的逐次原生值。HTTP 只读 `logs_2.sqlite`，按进程、对话、轮次及响应边界关联“请求体压缩→HTTP 200 响应头”，以 `44.693+ s` 显示估算；只有压缩日志时保留已知等待下限。缺少逐次计时的 WebSocket 等响应采用临时约定：**每轮仅首次计入 TTFT，后续暂按 0**。轮次原生 `task_complete.time_to_first_token_ms` 从任务启动起算，按日志起点差近似换算到首响应，标注“轮次首次近似”；不会复制到所有响应。首次尚未上报、缺失或无法一致换算时暂按 0 并明确标注，轮次完成且原生值到达后自动更新。0 是约定值而非实测零等待；实际 TPS 因此标为估算。HTTP 估值与首个已落盘输出项的时间明显冲突时弃用该配对并注明，回到上述约定。悬停可查看来源和原因；不再使用首个输出项等待上界作为 TTFT。
- 每次模型响应在模型名下显示传输方式 `HTTP` 或 `WebSocket`，同一响应先有 WebSocket 端点记录、随后进入 HTTP 时显示 `HTTP（WebSocket 回退）`。判断来自同对话、同轮次及响应边界内的客户端日志；复用连接未生成独立事件时，沿用同轮最近的传输记录并标注“沿用”，不冒充逐请求确认。悬停查看依据；不抓包、不改变请求协议，无可归属日志时明确显示未记录。趋势原始点悬停与 CSV 同步包含传输方式和回退标记。
- 同一轮次的多个模型响应相加；子代理作为独立对话显示，不叠加到父对话。
- 主卡片显示最新一次响应 TPS 和用量上报距今多久，另列最近 N 轮的平均 TPS；推理/可见输出分项及近 30 秒已记录消耗速度继续保留。
- 从浏览器导出当前对话最近 N 轮的响应明细 CSV，包含 `turn_id` 和轮次内响应编号。加载期间按钮标明已加载轮数，导出该时刻已加载的响应；完成后自动恢复最近 N 轮范围。
- 支持暂停显示、深浅主题及窄屏布局。暂停显示期间后台仍继续采集。
- 三个页面顶部均保留“对话明细 / 速度趋势 / 额度趋势”导航，突出当前页面，与暂停和主题操作区分开；滚动长明细时导航仍保持可见。“速度趋势”按模型分图，以推理档位和服务层区分曲线，可切换带点折线或散点。

## 速度趋势

趋势页位于 `/trends`，默认显示最近 **24 小时**，支持 1、6、12、18、24 小时、3 天、7 天快捷时间跨度和自定义起止时间。可筛选模型、推理档位、服务层以及主对话/子代理，并切换可见 TPS、实际 TPS，默认可见 TPS。横轴为用量上报时间，刻度随时间跨度调整；完整视图的纵轴为 TPS，从零开始。

每张图可以独立操作：先用鼠标左键点击图框选中，再在绘图区滚动鼠标滚轮，以鼠标位置为中心同时缩放时间轴和 TPS 轴；按住 Shift 时只缩放纵轴，按住 Ctrl 时只缩放横轴。按住鼠标左键拖动平移。默认纵轴从零开始，按当前显示的聚合趋势设置比例，叠加原始散点时不因个别极端点拉高纵轴。双击绘图区或点击“自适应”，按当前时间视图中显示的趋势调整两轴范围并留出边距；关闭滤波时按原始散点自适应。若当前时间视图内无数据，则使用该图全部显示数据。点击“恢复全图”清除缩放和平移，回到所选的完整时间范围与初始纵轴比例。图下方显示超出当前纵轴的原始点数量，可点击独立的“查看全部散点”临时展开全部原始值；再点击“恢复全图”即可回到趋势比例。也可使用该图的 +/− 按钮缩放，倍数以默认视图为参照。缩放和平移允许数据范围外留白，使鼠标下的数据位置保持稳定；这只调整视图，不扩展所选日志时间跨度、不改变滤波窗口或原始数据。实时刷新和窗口调整大小时保留视图，切换时间范围或数据筛选时恢复默认比例。同一时间只选中一张图，高亮边框及“已选中”提示显示当前选择；视图按钮在选中后启用。点击图框外或另一张图取消原选择，但保留已有缩放比例；实时刷新保留选中状态。键盘可用 Tab 聚焦图框，Enter 或空格选中，Escape 取消。未选中时及绘图区外的滚轮用于页面滚动与浏览器原有快捷操作。

默认按 **10 分钟时间窗口**滤波，窗口可设为 1–1440 分钟。推荐“耗时加权吞吐量”：同一模型、档位和服务层内，可见 TPS = 输出 token 总数（含推理）÷ 完整耗时总和。实际 TPS 将各响应生成耗时的上下界分别相加，用输出总数除以最大耗时总和得到速率下界，除以最小耗时总和得到速率上界；最小耗时为零时只给出下界。区间汇总包含全部有可靠总耗时的响应，不能直接平均各个 TPS。并发会话的耗时分别累加，因此不是按墙钟时间计算的总吞吐量。也可选中位数或等权均值，分别对样本速率上下界应用相同统计；关闭滤波时展示原始点。设置保存在本机浏览器。

每个聚合点位于时间窗口中间，大小表示累计响应耗时，悬停可查看样本数、token、耗时权重和原始 TPS 范围。当前未结束的窗口随新响应更新。空窗口不补零；遇到空窗，或相邻窗口的实际样本间隔超过窗口长度时，折线断开。连线只帮助观察窗口间趋势，不代表期间持续输出。 实际 TPS 单值使用实心点，范围或下界使用空心点；竖线表示有限区间，箭头表示没有有限上界或上界超出当前图框。区间点不直接连成确定速度曲线；默认叠加的原始点仅显示下界标记，悬停查看完整范围，关闭滤波时可见原始区间。

默认叠加淡色原始散点，也可关闭叠加；开关不改变当前缩放范围。悬停可查看每次通过去重且有可靠计时的响应用量记录。点击图下方图例，可独立隐藏或恢复对应档位、服务层的曲线与散点；图例始终保留，隐藏状态随实时刷新保留，各模型互不影响。切换图例时保留当前时间视图，重新计算纵轴；自适应只使用当前显示的曲线，全部隐藏时禁用缩放和自适应按钮。关闭滤波时只画原始散点，不直接连接。可见/实际 TPS 均包含推理 token，区别仅在分母是否扣除逐次首 Token 等待。无法计时的响应不画成零值，并单独显示数量；滤波只影响图表显示，不改变采集数据和对话明细。

图表按所选时间范围独立补读，不受主面板最近 N 轮限制；需要更早内容时会扩大发现范围，并从完整轮次边界逐步加载。补读期间保留已加载的图，并显示范围尚未读完，完成后自动补齐。主面板仍按自身 N 轮统计。归档日志始终参与同一时间范围的采集与趋势统计，不受对话列表的显示筛选影响。已跟踪日志移入或移出归档目录时，即使修改时间已超出启动发现天数，也会继续跟踪；同一文件移动保留增量读取和历史补读进度，同一对话 ID 不重复累计。重建或截断的日志仍按原规则重新读取。`--days` 继续限制首次发现的日志范围，`--days 0` 包含全部历史；图表选择更早范围仍会触发相应补读。

图表页面每秒刷新一次，后台日志轮询保持原设置。图表、脚本及样式全部内嵌在便携 exe 中，运行时仅访问 `127.0.0.1`，无需安装图表库或联网。

## 额度趋势与容量估算

独立页面 `/quota` 从本地 `token_count.rate_limits` 读取额度快照，无需监控工具登录或联网。默认显示最近 24 小时，可选 1、6、12、24 小时、7 天、30 天；开始/结束时间表单直接显示，点击“应用自定义范围”后按本机时区固定范围，快捷范围则随时间滚动。按 `limit_id` 和实际存在的主/次周期分别画剩余/已用百分比阶梯线。源数据有小数时保留小数百分比，只有整数时显示整数，不推造额外精度。显示最近上报、周期、重置时间及补读状态；重复快照不相加，缺失周期显示未记录，过了重置时间只提示等待更新，不假定恢复 100%。正常的重置时间秒级漂移不算换周期。

额度快照和每次响应的模型、速度、token 计量写到当前电脑的 `%LOCALAPPDATA%\CodexTPSLive`，按 Codex 数据目录和 `--quota-profile` 隔离 JSONL 记录；可用 `--data-dir` 改位置。每约 2 秒批量追加，正常退出再刷写，重启后按稳定检查点去重恢复。历史补读与最近 N 轮独立；已经记录的额度不因缩小 N 或原日志移走而消失。对话归档不删除已保存的用量，也不停止归档文件的后续采集；额度估算继续使用归档消耗。首次启用归档采集可能补回此前漏读的数据并修正估算，页面会显示补读进度；这不代表官方额度发生变化。记录不含提示词、回复、工具输出或认证信息，也不写入 Codex 日志目录。写入失败时页面明确提示，并暂存内存等待重试。`--quota-profile` 只是本地记录命名空间，不能验证当前登录身份。换账号后应另选资料名，并确保采集的源日志属于同一账号；调整图表起点不能隔离容量校准所用的历史。

模型加权成本使用 [Codex 官方标准积分表](https://learn.chatgpt.com/docs/pricing)（内置规则核对日期 2026-10-15），分别计算非缓存输入、缓存输入和输出；输入是每次请求的全部上下文，推理已含在输出中，缓存写入不另收 Codex 积分。推理档位通过实际 token 用量反映，不另加一个档位倍率。[官方速度说明](https://learn.chatgpt.com/docs/agent-configuration/speed)区分两种口径：订阅额度 Fast / ultra fast 为 2.5× / 8×，购买积分为 2× / 6×，可在页面切换。未知模型或速度不会被当成免费响应。

默认按 Codex 标准积分表，不套用未获确认的订阅长上下文倍率。可选“API 长上下文情景”：单次输入 **>272,000** token 时，整次请求输入/缓存 2×、输出 1.5×，再叠加速度倍率；这来自 [API 规则](https://developers.openai.com/api/docs/pricing)，页面明确标为假设，不声称是 Codex 官方订阅扣量规则。大上下文的全部输入、缓存和实际输出在两种情景下都会照实计入。

满额等效积分 = 校准基线之后完整区间的已计价响应成本之和 ÷ 对应已用百分点增量 × 100。容量校准使用**截至所选结束时间、已采集历史中的最新连续额度段**，不再随图表起点滚动；切换显示跨度不会删除已有校准样本或重建基线。图表范围只限制曲线、变化明细及目标模型的混合 token 比例样本，因此比例变化仍可能改变 token 换算结果。使用的是已采集历史，不保证覆盖整个额度周期；新补读的记录仍会更新估算。校准区间、覆盖和模型消耗在详情中单独显示，可能早于图表起点。

每段的首次正向百分比变化只建立基线，之前的首个观测区间可能采集不完整，因此不计入校准积分、百分点、响应覆盖或有效区间数。该区间落在图表范围内时仍保留在曲线与变化明细中，标明“起始区间，不参与校准”；对话明细中的实际用量与预计积分不受影响。建立基线后，须再观察到一次正向变化，才形成可用于估算的完整区间。

持续回退、套餐/周期变化、重置时间变化超过 120 秒或上报空窗超过 6 小时会重新分段，并按上述规则重新建立基线，不跨段推算。并发对话可能短暂上报旧值：同周期回退须距前一有效快照不超过 2 分钟，且低位上报持续不超过 2 分钟；观察到恢复后保留为灰色空心点，不用该快照另建基线。恢复可以等到下一次稀疏上报，但不得超过前一有效快照后的 6 小时或跨周期；例如 `34% → 33%` 后没有继续上报低值、5 分钟后回到 `34%`，不会仅因中间静默而重建基线。**回退幅度不限于 1 个百分点**。对应响应用量仍照常计入完整校准区间。未观察到恢复、低位上报持续超过 2 分钟，或套餐、周期和重置时间发生上述变化时，不假定是迟到快照。按百分点端点约 ±1 的分辨率给出容量区间，跨度较小时标为暂定；这不是统计置信区间。显示响应覆盖、模型消耗和逐次百分点变化依据；历史尚未补齐或有未计价响应时，会标明可能偏低，上界可能未知。没有完整区间或可计价样本时保留曲线并等待更多数据。

选择目标模型和速度后，首屏两张卡直接显示**满额预计积分 / 剩余预计积分**，并分别显示对应的**预计可用混合 token**，无需展开详情查找积分。token 容量均为非缓存输入、缓存输入和输出混合后的一个总处理量，包含重复发送的上下文，并非可新增的文本量。比例按所选时间范围、额度桶内有效记录的 token 总量加权，不平均每次请求的百分比。目标模型达到 10 次有效响应时使用自身记录；不足时使用 `gpt-6-astra` 或 `gpt-6.1-sol` 中样本更多者。参考模型仍不足 10 次时标明少样本；两者均无记录时才使用目标模型已有的少量记录，三者均无记录则等待采集，不假设固定缓存或输出比例。10 次只是选择参考来源的阈值，不代表统计置信度。页面显示比例、来源模型、响应数量和样本时间范围。

将参考记录中的每次实际输入、缓存和输出按目标模型与速度重新计价，累计成本除以混合 token 总量，得到每百万混合 token 的等效成本；满额/剩余等效积分除以该成本得到两个容量值，不先取整请求数。可选长上下文情景逐次判断，避免用平均上下文跨过阈值。积分校准、模型消耗、逐次变化和规则放在可展开的详情中。估算假设本机所选日志来自同一账号并覆盖同期消耗；其他电脑、云任务、共享功能及服务器上报延迟都会影响结果。等效积分不是服务端公开的订阅余额，购买积分表也不能直接决定订阅总额度，页面不会将推算值作为官方账单。

额度图还提供**预计耗尽时间**，默认参考最近 6 小时的实际额度消耗，可选 1、6、12、24 小时或整个图表范围。在绘图区横向拖拽即可选择参考区间，松开后才提交计算；也可展开“手动选区”填写时间，按 Esc 取消正在进行的拖拽。选区固定在所选时间，预设时长则随图表滚动；更改图表起止范围会恢复预设参考时长。拖拽只更新选框，不逐帧重算，不改变图表起止范围或满额积分校准基线。

平均消耗速率 = 选区内首末有效快照的已用百分点差 ÷ 两条快照的实际时间差；预计耗尽时间 = 最新有效快照时间 + 剩余百分点 ÷ 平均消耗速率。预测使用未压缩的原始额度快照，独立于积分计价与 token 容量估算，显示实际采样区间、每小时消耗和数据截至时间。只使用当前连续额度段，跳过已确认的迟到快照；跨重置、回退或上报空窗时提示重选，样本不足或没有观测到消耗时不编造日期。若重置早于外推耗尽时间，明确提示本周期预计先重置，上方日期只是忽略重置的线性外推。百分点取整、补读与未来使用强度变化均会影响结果，预测不是官方额度保证。

## 日志与名称

每份日志以首个有效 `session_meta.id` 确定所属对话。子代理日志可能带有父对话的继承历史；后续不同 ID 的元数据不会覆盖本文件的身份、父关联或代理名称。继承前缀中的旧轮次、模型和用量不计作子代理的新请求，从 `thread_settings_applied.thread_id` 明确匹配本文件所属对话的边界开始计量。含这类继承身份的日志会从头分批重建，以正确定位边界，界面仍使用所设最近 N 轮窗口。旧版本已保存的额度检查点在重放时复用已有记录，避免身份修正后重复累计；不会清空原始日志或额度历史。

对话标题优先使用当前 Codex 数据目录下 `session_index.jsonl` 的最新非空名称，同一 ID 按 `updated_at` 选择；程序跟随本地索引变化刷新，分支对话和重命名也使用该名称。索引缺失时，对话标题回退到首次有效用户文本的短预览；轮次标题仍使用有效用户文本预览，跳过环境、工作区规则和 Referenced chats 等注入说明。子代理缺少标题时，以任务名代替，其次使用昵称，已有实际标题则保留。左侧不重复显示与名称相同的标题。不显示完整聊天或工具输出。没有有效时间或轮次边界的旧日志会显示警告、未归属用量或“TPS 不可用”，不会伪造零 TPS。

子代理名称来自本地 `session_meta` 的 `agent_path`、`agent_nickname` 和 `agent_role`，优先使用顶层字段，缺失时读取 `source.subagent.thread_spawn` 的同名字段。即使从尾部加载最近轮次，也会读取文件头的元数据，无需扫描父对话或联网。仅有昵称时直接显示昵称；未记录名称的旧日志显示“名称尚未记录”。

服务层标签读取本地 `thread_settings_applied` 事件中的 `thread_settings.service_tier`：`fast` 或 `priority` 显示 `fast`，`default` 显示 `default`，`ultrafast` 显示 `ultra fast`；缺失、`auto` 或其他无法确定的值显示 `unknow`。从尾部加载时也读取选中轮次边界与前一个累计用量检查点之间的设置记录，并保留其时间。从 [Codex 官方子代理规则](https://learn.chatgpt.com/docs/agent-configuration/subagents)可知，子代理的服务层跟随主对话偏好；子代理没有自身设置记录时，程序沿父对话关联找到主对话并补全，标注“继承”。对话标签显示主对话当前偏好，历史轮次及响应按轮次开始时间匹配当时的主对话设置，不会用当前开关替换旧记录。主对话日志或对应历史设置不在已加载范围时仍为未知，可扩大 N 或通过 `--days 0` 加载相关对话。全局配置不用于回填历史。该标记表示请求设置，不保证服务端实际采用相同处理层级。判定同时参考 [Codex 配置文档](https://learn.chatgpt.com/docs/config-file/config-reference)和 [Fast mode 官方说明](https://developers.openai.com/api/docs/guides/fast-mode)，运行时无需访问这些页面。

## 统计口径

输入是每次模型请求处理的上下文 token，不仅是新输入的消息。缓存命中属于输入，推理属于输出，不能重复相加。缓存写入单列；“非命中输入”是输入减去缓存命中，并不排除缓存写入。

**默认可见 TPS = 输出 token（含推理）÷ 完整响应耗时；实际 TPS = 同样的输出 token ÷（完整耗时 − TTFT）。** 逐次原生 TTFT 优先，HTTP 压缩→响应头为近似等待；缺少逐次计时时按每轮仅首次、其余暂按 0 的约定计算，标记 `≈`。暂按 0 时，实际 TPS 与可见 TPS 相等。首响应使用轮次原生 TTFT 扣除任务开始至首响应开始的日志时间差近似换算，并非逐请求实测；首次尚未上报或无法一致换算时也暂按 0 并注明。仅有压缩日志的等待下限 L 时，输出 O、完整耗时 D 可给出实际 TPS 下界 `≥ O/(D−L)`；不使用首输出项等待上界推算。汇总累计对应响应的输出和计算耗时，并显示估算、暂按 0 的数量，不混用全量 token 与部分耗时。最近响应卡显示报告时间，不把旧记录称为当前生成速度。

在线 API 新增 `tps.perceived` / `tps.actual`，趋势新增 `perceived_tps` / `actual_tps`，CSV 追加 TTFT、来源和新 TPS 列。原 `output` / `effective_tps` 仍为含等待的输出速率，旧 `visible` / `visible_tps` 保持“非推理输出 ÷ 完整耗时”的兼容含义；界面不再把旧字段称作可见 TPS。离线 codex-tps CLI 保持原口径。SQLite 使用内嵌纯 Go 驱动，运行时无需 Python、SQLite 安装或联网；只读打开现有数据库，不修改 Codex 配置、不增加遥测、不代理请求。监控仍有本机读盘和计算开销，不承诺资源开销绝对为零。 `actual_range=true` 时，`actual` 保持空，使用 `actual_min` / `actual_max` 表示实际 TPS 范围；此时 min 有值而 max 为空表示没有有限上界，不是零或无数据。趋势和 CSV 对应字段是 `actual_tps_min` / `actual_tps_max`，同时导出生成耗时上下界。`ttft.assumed` / CSV `ttft_assumed` 明确标识暂按 0 的约定值，`ttft_source` 和 `ttft_note` 提供来源；旧 `upper_bound` / `ttft_upper_bound` 兼容字段固定为 false。

近 30 秒消耗速度 = 所选轮次内最近 30 秒日志上报的 token / 30 秒。它度量用量到达日志的速度，与输出 TPS 不同。Codex 通常在响应完成后才上报用量，因此数字会跳变；进行中的响应没有可靠的逐 token 计数，不以字符数估算隐藏推理或未上报用量。这里的统计是本地日志分析，不是最终账单。

累计检查点用于去重；重复检查点不再计数。程序等待半行写完后才处理，发现文件截断、重建或迁移时重新建立该对话统计。若计数器重置或某些日志字段缺失，界面说明数据限制。分轮次依赖 `task_started`/`turn_context` 的 `turn_id`，一次用户任务可能包含多次模型响应。

## 源码构建

```powershell
pwsh -File .\build-portable.ps1
```

构建需要 PowerShell 7、PATH 中的 Go 和上游绘图依赖，首次下载依赖需要网络；Go 未加入 PATH 时可传 `-GoExe` 指定本机 Go 可执行文件。构建脚本通过自身目录定位源码，生成未压缩的 `dist` 目录和上述便携 ZIP，固定覆盖最新发布文件；使用 Windows x64 基线指令集并禁用 CGO。上述构建工具仅用于生成发布包，使用便携版的电脑无需安装它们。生成后的实时工具运行期间没有出站请求。原有 `cmd/codex-tps` 保留 CSV/PNG 离线分析行为。

只更新便携版的说明、许可证及压缩包时，可复用 `dist` 中的现有程序，无需重新编译或重启监控：

```powershell
pwsh -File .\scripts\package-portable.ps1
```

推送 `v*` 版本标签后，GitHub Actions 会在 Windows runner 上调用同一个 `build-portable.ps1`，自动发布 Windows 便携 ZIP、独立 EXE 和包含两者校验值的 `SHA256SUMS` 到对应 Release。发布标签与 `live_server.go` 中的程序版本应保持一致。GitHub 自动生成的 Source code 压缩包用于开发；直接运行请下载 Release Assets 中的 `codex-tps-live-windows-amd64.zip`，或单独的 `codex-tps-live.exe`。
