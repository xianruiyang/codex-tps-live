指标含义与隔离方式

智能测速是可选的调度模式，不额外增加测速项目。仅按已勾选项目依次完成 Clash、HTTP、WebSocket 阶段。Clash 默认上限 500 毫秒且可修改；任意一次失败或超过上限会排除整节点。HTTP 或 WebSocket 失败只排除该项目后续轮次。未选 Clash 时不做延迟筛选。跳过的计划轮次不会发请求，也不计为失败，原因保留在卡片明细与 CSV。

Clash 延迟使用独立 Mihomo 的原生 /delay 接口，沿用本机 Clash 手动测速地址及 unified-delay 设置，也可在上方更改。它是原生 HEAD 延迟，统一延迟开启时通常发两次 HEAD 并取第二次成功请求；与 Codex 两项包含建连和 TLS 的首响应时间口径不同。

Codex HTTP 请求模型列表，WebSocket 请求响应地址的 Upgrade 入口。401 JSON 表示到达鉴权入口，101 才表示接受 WebSocket 升级。两项不读取 Codex 登录凭据或发送生成事件，不能验证认证后的推理或持续连接稳定性。显示中位数时只采用成功样本，失败与超时单独保留，逐次结果可展开或导出。

读取当前用户的本地订阅及已有 provider 缓存；当前订阅优先使用生成的生效节点，其他订阅使用原始定义，不执行增强脚本或刷新远程订阅。代理组、规则和脚本不当作节点。不同订阅的同名节点独立隔离；无法确定依赖时明确报错。

即时测速点击开始后探测选中项目；已启用的计划会按间隔自动探测。使用独立的 127.0.0.1 端口，保持当前节点、系统代理、TUN 和 Codex 请求链路。停止或完成后清理；刷新页面不重新开始测试。即时测速进度逐项保存在本机，重启后继续未完成项；主动停止的任务不会自动重启，可导出 CSV。计划及其历史保存在本机数据目录，重启后可继续查看。
