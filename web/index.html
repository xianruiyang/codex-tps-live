统计口径与更新方式

预计积分按当前选择的 Codex credits rates、服务层和上下文规则计算，是等效消耗，不是官方精确余额。会话列表与汇总均取最近 N 轮；轮次与响应展示各自消耗。父对话不自动包含子代理，避免重复累计。未知模型或服务层等未计价响应显示“未知”或“部分”，并列出覆盖数；不当作免费。

首 Token 耗时优先显示原生 TTFT；现有原生值是轮次级，保留在轮次表，不复制给每次响应。逐次响应按进程、对话、轮次和时间边界，从本机 logs_2.sqlite 的请求压缩及 HTTP 200 响应头日志计算近似等待，显示 xx+ s；+ 表示估算，尚不包含响应头后的首 token 等待。只有压缩日志可归属时，显示“响应开始→压缩日志”的已知等待下限；WebSocket 等未记录 HTTP 压缩日志的响应使用首个输出项的等待上界（≤），按此计算实际 TPS 范围或下界，悬停可看依据。可见 TPS = 输出 token（含推理）÷ 完整响应耗时；实际 TPS = 同样的输出 token ÷（完整耗时 − 逐次等待），估算值加 ≈。汇总对全部可计时响应累计输出及生成耗时边界，得到加权范围，并注明单值/范围数量；默认显示可见 TPS。只读本机日志，不修改 Codex 设置，不安装采集器或介入请求链路。

模型旁显示日志中的 Fast 请求设置：fast / priority 为开启，default 为关闭，ultrafast 单独标示。子代理自己的日志优先；没有独立记录时按 Codex 规则从主对话继承，并标注“继承”。对话标签取主对话当前偏好，历史轮次和响应按轮次开始时间匹配；缺少对应历史记录时仍显示未知。该标记不保证服务端实际采用相同处理层级。

统计默认取每个对话最近 10 轮，可在顶部设置 N；进行中的轮次也计入。左侧用量、统计卡片、轮次列表与 CSV 导出使用同一个范围。“全部 / 主对话 / 子代理”和“显示归档对话”只筛选列表，不合并父子用量；隐藏或归档对话不会移除速度趋势、消耗记录或额度估算样本。独立的“速度趋势”页按时间范围读取，不受最近 N 轮限制。

输入是模型每次请求处理的完整上下文，包含历史、工具结果和指令，并非只计算你新输入的文字。缓存命中属于输入；推理属于输出。各轮次累计其模型响应的 token，同一上下文重复处理会再次计入。

主数值显示最近一次响应的输出 TPS，并标注用量上报距今多久；它与 N 轮平均值分开。平均 TPS = 有可靠时间边界的输出 token 总数 ÷ 这些响应的耗时总和。沿用 codex-tps 的日志时间边界，包含首 token 等待，排除响应之间的工具执行时间；不是纯解码 TPS。无法计时的用量仍计入 token，TPS 显示“—”。

近 30 秒消耗速度按所选轮次内的用量上报时间统计。用量通常在响应完成后上报，因此会跳变；零值表示这个窗口没有收到记录，不表示模型没有工作。不会用字符数估算尚未上报的 token。

按更新时间优先读取最新对话，从文件尾部定位最近 N 轮；扩大 N 时按需补读更早轮次。未读取全部历史时标明已加载轮数，加载期间 CSV 导出已加载的响应。默认每 0.5 秒增量读取与刷新页面，每 5 秒发现新日志。只有完整 JSONL 行才会入账。子代理单独列为对话。只读取本地日志；页面、字体和脚本均内置，运行期间仅连接本机。
